# AetherFlow Threat Model

## 1. Overview

This document maps CWEs and privilege boundaries across the **AetherFlow v4.0.1** architecture:

- **Control Plane (`af-api`)**: Unprivileged Rust (`Axum` + `Tokio`) HTTP/WebSocket server serving the external **Leptos Rust WebAssembly (`frontend-rs`)** SPA from `web/dist` (`STATIC_DIR`), running as `User=aetherflow` under `ProtectSystem=strict`, `ProtectHome=read-only`, and `NoNewPrivileges=yes`.
- **Privileged Runner (`af-runner`)**: Root daemon listening exclusively on `/run/aetherflow/runner.sock` (`0660 root:aetherflow`).
- **Scoped File Manager (`af-files` & `af-api::mcbrowser`)**: Native McBrowser tenant storage under `/var/lib/aetherflow/mcbrowser` (`0700`).
- **Persistence (`af-db` & `af-host`)**: Bundled SQLite (`rusqlite`) in single-writer `WAL` mode with AES-256-GCM (`enc:v1:`) secret encryption, volatile memory zeroization (`af-models::secret_zeroize`), and manifest-verified online backups.

## 2. CWE Mapping & Mitigations

### CWE-284 / CWE-285: Improper Access Control & Authorization

| Component | Threat | Mitigation |
| :--- | :--- | :--- |
| Route hierarchy (`af-api`) | Unauthenticated or cross-role access | Three-tier API router (`/api/v1/public`, `/api/v1/auth` with JWT + revocation checks, `/api/v1/admin` with live DB `role == "admin"` verification), plus top-level `/plugins/:id/{ui,proxy}`, legacy `/api/*` compatibility aliases, `/health*`, and `/metrics`. `POST /api/v1/auth/ai/support` enforces live admin RBAC (`403` for non-admins); `POST /api/v1/auth/ai/chat` restricts paid cloud providers (`openai`, `gemini`, cloud `anthropic`) to administrators by default (`403 AI_PROVIDER_ADMIN_ONLY`, opt-in via `AF_AI_ALLOW_USER_CLOUD_PROVIDERS=1|true`) while keeping local runtimes accessible without attaching stored cloud API keys. On empty-DB hosts, `POST /api/v1/public/auth/setup` requires `/var/lib/aetherflow/.setup-bootstrap-token` (or `AETHERFLOW_SETUP_TOKEN`) on proxied/non-loopback calls (`403 SETUP_TOKEN_REQUIRED`), while direct unproxied loopback (`127.0.0.1:8080`) requests bypass the token until the first admin is created. |
| Plugin token RBAC & proxy (`af-api`) | Plugin token used outside authorized routes or for recursive proxy calls | `auth_middleware` (`plugin_claims_allow_request`) enforces segment-boundary `api_scopes` against manifest permissions and default-denied prefixes on plugin-to-API calls; the plugin reverse proxy (`backend-rs/crates/af-api/src/plugins/proxy.rs`) unconditionally rejects plugin tokens (`403 PLUGIN_PROXY_FORBIDDEN`) to block recursive proxying. |
| Host filesystem picker (`/api/v1/auth/fs`) | Non-admin user enumerating host directories | Restricted strictly to live-verified active `admin` accounts before any path canonicalization or existence checks; ordinary users are confined to McBrowser (`af-files`). |
| Peer Clustering (`af-api::peers`, `af-runner`, `af-transcode`) | Unauthorized peer access, privilege escalation across peers, tunnel exposure, or transcode worker breakout | Legacy single-master clustering (`/cluster/v1/*`, gRPC `:50051`, `CLUSTER_PSK`, `CLUSTER_ALLOW_INSECURE_LOOPBACK`) was permanently removed in Migration 26. Peer Clustering separates: (1) public HTTPS bootstrap (`POST /api/v1/peer-pairing/request`, 4 KiB cap, 5 req/min/IP, 300 s clock-skew check, single-use 10-minute window, 6-digit code confirmation), (2) a dedicated `afpeer0` WireGuard interface and `SO_BINDTODEVICE`-bound tunnel listener (`<tunnel_ip>:9443`) using distinct link (`X-AF-Link-Token`) and grant (`X-AF-Grant-Token`) bearer tokens stored in mode `0640` (`root:aetherflow`) files under `/etc/aetherflow/peers/tokens/` (while `afpeer0.key` and attempt-scoped `pending/` issuer tokens remain `0600` root-only), (3) fail-closed 8-area grants starting at `None` with non-grantable local-only routes (`PEER_SCOPE_DENIED`), unmapped route rejection (`PEER_ROUTE_UNCLASSIFIED`), and `<< 1 s` revocation teardown of HTTP streams, WebSockets, and `SIGKILL` of remote transcode jobs, (4) NFSv4.2 bound exclusively to `afpeer0` with tunnel-IP-pinned exports, and (5) `af-transcode-worker.service` running as `User=jellyfin` with `SO_PEERCRED` caller UID verification (`AF_TRANSCODE_ALLOWED_PEER_UIDS`), `PrivateNetwork=yes`, `RestrictAddressFamilies=AF_UNIX`, `ProtectSystem=strict`, `DevicePolicy=closed`, local-only `ffmpeg` protocols, and secret-free `/etc/aetherflow/transcode.env` (never `/etc/aetherflow/aetherflow.env`). See [Peer Clustering](./peer-clustering.md). |
| Subdomain Gateway Basic Auth, Apache `htpasswd` & `.aether.local` (`af-api` / `af-runner`) | Offboarded admin retaining Basic Auth access, or LAN/Tailscale/CGNAT peers reaching McVNC & protected apps unauthenticated | External `<app>.<baseDomain>` and internal `<app>.aether.local` requests enforce live administrator sessions (`__Host-aetherflow_app` on HTTPS, `aetherflow_local_app` on HTTP `*.aether.local`, or `aetherflow_session`) or rate-limited Basic Auth across all **10** protected apps (including `rutorrent`). `verify_proxy_basic_credentials` checks exclusively active SQLite `users` rows (`role == "admin"`, `totp_enabled == 0`, matching bcrypt hash) with no `.master.creds` fallback. Local `127.0.0.1:8087` `rutorrent.conf` enforces `<RequireAll>` (`Require local` + `/etc/aetherflow/rutorrent-proxy-token.conf` matching `X-Aetherflow-Rutorrent-Token`) and maps `X-Aetherflow-User` to `REMOTE_USER`; legacy `/etc/apache2/AetherFlow/htpasswd` is reserved for custom Apache blocks or non-loopback `BIND_ADDR`, and `rutorrent.htpasswd` is created only when `AF_APACHE_LISTEN_ALL=1`. Authenticated Tailscale (`100.64.0.0/10`) clients remain permitted on `.aether.local`, while optional unauthenticated LAN bypass (`AF_ALLOW_UNAUTH_LOCAL_LAN=1`, default `false`) is restricted strictly to RFC 1918, link-local, and IPv6 ULA (unconditionally excluding `100.64.0.0/10` and loopback). |

### CWE-22 / CWE-59: Path Traversal & Improper Link Resolution (Symlink Following)

| Component | Threat | Mitigation |
| :--- | :--- | :--- |
| Native McBrowser (`af-files`) | Escaping `/var/lib/aetherflow/mcbrowser/user-<id>` via `..`, symlinks, mount boundaries, or wide-tree FD exhaustion | Descriptor-confined capability traversal rejects `..`, NUL bytes, backslashes, and symlinked mutation parents while enforcing `0700` per-user roots. Opt-in internal symlink reads use Linux `openat2` confinement and target identity verification, and both `walk` and `walk_for_search` enforce `depth <= MAX_PATH_COMPONENTS (64)` while queuing relative path components (never open `OwnedFd`s) across BFS scans. Recursive deletion (`remove_tree_with_outcome` / account cleanup) enforces `openat2(..., RESOLVE_NO_XDEV)` and `st_dev` mount-boundary guards returning `RemoveTreeOutcome { removed_bytes, skipped_mount_paths }` by skipping mount points without unlinking mounted host storage. |
| Declarative Package Executor (`af-runner`) | Arbitrary file overwrite or `chown -R` on system roots via symlink planting | Applies to the 9 opt-in declarative Rust recipes (`AETHERFLOW_ENABLE_RUST_PACKAGES=1`, default OFF): `validate_filesystem_path` inspects every ancestor component via `lstat` (`symlink_metadata`), rejects symlinks with `SecurityViolation`, and blocks shared system paths (`FORBIDDEN_EXACT_PATHS`, `SHARED_SYSTEM_CHOWN_PATHS`); config reads delegate to descriptor-confined `confined_fs::read_confined_text` (`2 MiB` cap). |
| Release & Backup Engines (`af-release`, `af-host`, `deploy/release-manager.sh`) | Malicious archive entries, decompression bombs, untrusted `--config`, or symlinked staging/helper paths | `ensure_no_symlink_ancestors`, exclusive `0700` staging directories (`create_new`, same-filesystem root-`0700` staging with FD `fchown`/`fchmod` before `sync_all()` and `dirfd` `renameat` + parent `fsync` during Stage 0 migration and Stage 4 restore), `512 MiB` archive download cap, per-entry and cumulative (`2 GiB`) tar decompression caps, rejection of tar symlink/hardlink/device entries, `O_NOFOLLOW` 31-key `--config` allowlist (forbidding secret tokens and provenance-bypass flags), atomic same-FS `0755 root:root` regular-file synchronization of `/opt/AetherFlow/packages/`, `/usr/local/bin/AetherFlow/*`, `/usr/local/bin/af-certbot-sync`, `/usr/bin/af-certbot-sync`, and `/usr/bin/af-systemd-sandbox`, and mandatory `SHA256SUMS` + Sigstore/SLSA v1 provenance (unless `AETHERFLOW_SKIP_PROVENANCE_VERIFY=1` is set in a direct `--local` CLI or `deploy/release-manager.sh` process environment, or in a root-owned non-world/group-writable `/etc/aetherflow/aetherflow.env`; never forwarded by `af-runner`) + `.manifest.json` verification before extraction. |

### CWE-78: OS Command Injection & Privilege Escalation

| Component | Threat | Mitigation |
| :--- | :--- | :--- |
| Privileged Runner (`af-runner`) | Unprivileged API or plugin process executing arbitrary root commands, or orphaned child process groups holding locks | `SO_PEERCRED` + `/proc/<pid>/exe` caller verification rejecting plugin binaries and scripting interpreters; strict regex allowlists on unit names (`SAFE_SERVICE_NAME`), package IDs (`SAFE_PKG_ID`), usernames (`SAFE_USERNAME`), and APT packages (`SAFE_APT_PKG_NAME`). Subprocesses run under tracked process-group supervision (`af-release::process_group` re-exported by `af-runner::bounded_command`, 20 s daemon shutdown drain `< 30 s TimeoutStopSec` reaping `-pgid` before exit, and stdin JSON credential delivery for Dispatcharr rather than process environment variables). All declarative steps (`DeclarativeStep`) execute shell-free direct `execve` argv vectors with `stdin(Stdio::null())` and `process_group(0)` (`DeclarativeStep::RunCommand` has been removed and `rclone` unmount uses shell-free `UnmountPaths` gated on `only_if_delete_data: true`); **known boundary caveat**: all **77** catalog packages default to Bash installers under `/bin/bash` (`AETHERFLOW_ENABLE_RUST_PACKAGES` defaults OFF), and **68** remain Bash-only when opt-in Rust recipes are enabled. |
| Managed Plugin Backends (`af-api` -> `af-runner`) | Managed plugin backend or `on_stop` hook inheriting `aetherflow` API OS identity or reaching host-loopback services | `af-api` delegates lifecycle control over `runner.sock` (`/v1/plugins/{start,stop,status,token}`) to `af-runner`, which verifies unified cgroup v2 (`/sys/fs/cgroup/cgroup.controllers`) and `systemd >= 249`, re-validates `plugin.manifest.json`, launches hardened transient `aetherflow-plugin-<id>.service` units (`DynamicUser=yes`, `ProtectSystem=strict`, `InaccessiblePaths` masking control-plane state and `/run/aetherflow-transcode*`, read-only assets/token mounts, `SocketBindDeny=any`, `SocketBindAllow=ipv4:tcp:<allocated_port>`, `IPAddressDeny=any`, `IPAddressAllow=localhost`; see [Security Guide](./security.md)), verifies UID/GID separation, and fails closed (`503 PLUGIN_ISOLATION_UNAVAILABLE`).<br/>**Residual loopback caveat**: Units block outbound LAN/internet egress and unauthorized binds, `/metrics` requires authentication, and loopback `rutorrent` requires `/etc/aetherflow/rutorrent-proxy-token`, but without `PrivateNetwork=yes` a managed plugin can still initiate TCP connections to sibling loopback-bound Marketplace apps on `127.0.0.1:<port>`. |
| Human-Gated FlowAI (`af-api`) | Prompt injection triggering destructive host commands | LLM output is untrusted; proposed service `restart`/`stop` actions are queued in `pending_actions` (Approval Inbox) and cannot execute without explicit administrator approval (`POST /api/v1/admin/actions/:id/approve`). |
| Self-Updater (`af-runner` `/v1/self-update`) | Command injection or caller crash during updater launch | Request channel/command validated via `af_release::validate_self_update_request`; launched in a dynamic transient unit (`aetherflow-self-update-<command>-<channel>-<8hex>.service` via `systemd-run --collect`) with non-secret environment vars passed via `--setenv`, a `0600` config snapshot (`<jobs_dir>/<unit>.conf`) read by the worker, and durable `0600` JSON receipts in `<data_dir>/.self-update-jobs/<unit>.json`. GitHub tokens are not forwarded (workers read them directly from `/etc/aetherflow/aetherflow.env` into redacted/zeroized memory); runner path resolvers (`resolve_af_cli_binary`, `resolve_release_manager_script`, `resolve_sandbox_script_path`, `resolve_af_transcode_binary`, `resolve_setdisk_script_path`, `package_script_roots`) prefer explicit env overrides, then immutable `env::current_exe().parent()` release artifacts ahead of `/opt/AetherFlow/current/...` and `/usr/local/bin/af` (gating any relative CWD fallbacks strictly to non-root test runs). |

### CWE-613 / CWE-384: Session Expiration & Revocation

| Component | Threat | Mitigation |
| :--- | :--- | :--- |
| JWT lifecycle (`af-api`, `af-db`) | Stolen, weak-secret, or logged-out tokens remaining usable in SQLite or heap RAM | Startup rejects `JWT_SECRET` values shorter than 32 trimmed bytes or containing ASCII control characters. 15-minute HS256 access token expiry (`exp`) with a 2-hour refresh grace window and 30-day hard session cap (no separate refresh token). All human-session surfaces (HTTP API middleware, `/api/v1/public/auth/verify`, Subdomain Gateway, `__Host-aetherflow_app` & `aetherflow_local_app` cookies, `/metrics` admin session auth, optional authenticated `GET /api/v1/public/marketplace`, WebSockets, and OIDC `/authorize`) validate sessions uniformly via `verify_active_session_on_conn` against SQLite `revoked_tokens`, unexpired `active_sessions`, client fingerprint, active user status, and `sessions_revoked_after`. `/refresh` fails closed with `401` on deleted `active_sessions` rows (preventing resurrection) while preserving a 10-second strict-fingerprint in-memory `ROTATED_TOKEN_GRACE` window gated on a live `active_sessions` `leaf_jti` row for concurrent browser tabs; both `ROTATED_TOKEN_GRACE` (storing successor tokens in volatile-zeroized `SecretString`) and `ROTATED_SESSION_SUCCESSOR` prune expired entries on every insert, enforce `4096`-entry capacity caps, and run a 60-second background sweep. |
| Account deletion (`af-api`) | Deleted user retaining active session or stranding last admin | Immediate transactional deletion revokes JWT sessions (`active_sessions` + `revoked_tokens` + immediate grace eviction), Subdomain Gateway Basic Auth (which resolves live admin `users` rows only), and OIDC tokens; verifies live owner existence on OIDC introspection and WebSocket upgrades; enforces last-usable-admin protection; and schedules durable `account_storage_cleanup`. Only hosts using legacy static Apache `htpasswd` fallback (custom Apache blocks, non-loopback `BIND_ADDR`, or `AF_APACHE_LISTEN_ALL=1` ruTorrent) require manual `htpasswd` cleanup. |

### CWE-311 / CWE-89: Cryptographic Storage & SQL Injection

| Component | Threat | Mitigation |
| :--- | :--- | :--- |
| Stored & in-memory secrets (`af-db`, `af-models`) | Plaintext credentials in SQLite backups, debug logs, or freed heap spare capacity | AI provider keys (`settings`), `users.totp_secret`, `streaming_servers.api_key`, `notification_channels.config`, `/var/lib/aetherflow/.master.creds`, and SQLite `system_config.master_credentials` are encrypted at rest with **AES-256-GCM** (`enc:v1:<base64(nonce \|\| ciphertext)>`) keyed by `AES_MASTER_KEY`. Ephemeral key/PEM/token buffers use `af_models::secret_zeroize::{SecretString, SecretBytes}` (volatile zeroization across full `0..capacity` backing storage on drop with `[REDACTED]` `Debug` formatting, paired with redacting `Debug` impls on settings payloads). OIDC client secrets are SHA-256 hashed (`oidc_clients.client_secret_hash`), the OIDC RS256 signing key is stored at `/var/lib/aetherflow/oidc_rsa.pem` (`0600`), and `GOOGLE_CLIENT_SECRET` is environment-only. |
| SQLite queries (`af-db`) | SQL injection | Parameterized `rusqlite::params![]` queries throughout; online backups use `VACUUM INTO` (default) or `rusqlite::backup::Backup` inside private `0700` staging directories. |

### CWE-918 / CWE-601: SSRF & Host Header Poisoning

| Component | Threat | Mitigation |
| :--- | :--- | :--- |
| Outbound Webhooks (`backend-rs/crates/af-api/src/notifications_ext/webhook.rs`) | SSRF against loopback, link-local, or private LAN targets | Outbound webhook validation blocks loopback, unspecified, link-local, metadata, multicast, and RFC1918/CGNAT/ULA private targets by default (`AETHERFLOW_ALLOW_PRIVATE_WEBHOOKS=1` opts into RFC1918/CGNAT/ULA LAN targets while continuing to block loopback, link-local, and metadata). |
| Peer Pairing Bootstrap (`backend-rs/crates/af-api/src/peers/pairing.rs`) | SSRF against internal services or metadata endpoints via pairing strings | Initiator HTTPS pairing requests enforce OS-trusted TLS with redirects and proxy env overrides disabled, resolve and pin DNS targets, unconditionally block loopback, link-local/cloud metadata, unspecified, multicast, broadcast/reserved, and `AF_PEER_TUNNEL_CIDR`, and block RFC 1918, CGNAT (`100.64.0.0/10`), and IPv6 ULA (`fc00::/7`) unless `AF_PEER_ALLOW_PRIVATE_PAIRING_URLS=true` is explicitly enabled. |
| Streaming Collectors & FlowAI Endpoints (`af-services` `streaming.rs::validate_server_url`) | SSRF against cloud metadata, self-targeting `aetherflow-api`, or unsafe redirects | Intentionally permits loopback, RFC1918/ULA LAN, and RFC 6598 CGNAT (`100.64.0.0/10`, set `AETHERFLOW_BLOCK_CGNAT=1` to block) hosts so local and Tailscale Jellyfin/Emby/Plex and LM Studio/Ollama/Anthropic-Local endpoints work natively, while blocking unspecified (`0.0.0.0`/`::`), link-local (`169.254.0.0/16`, `fe80::/10`), cloud metadata endpoints, multicast, proxies, and HTTP redirects. FlowAI defaults `anthropic-local` to `http://127.0.0.1:8081` (`DEFAULT_ANTHROPIC_LOCAL_ENDPOINT`), strips cloud API keys on all local dispatches, and rejects any AI endpoint targeting `aetherflow-api`'s own host/port (loopback, unspecified, or `BIND_ADDR` on configured `PORT`, including implicit `80`/`443`) with `400 AI_SELF_TARGET_REJECTED` at save, probe, and chat dispatch time. |
| Host Header Validation & Refresh Rate Limiting (`ALLOWED_HOSTS`) | Host header poisoning in OAuth/OIDC redirects, CSP `connect-src`, or unauthenticated `/refresh` floods | `host_validation_middleware` executes outside `security_headers_middleware`, implicitly trusting only canonical loopback IP literals (`127.0.0.0/8`, `::1`), `localhost`, `baseDomain`, enabled per-app domains, and authenticated `.aether.local` domains; non-loopback IPv4/IPv6 literals must appear in `ALLOWED_HOSTS`, `PUBLIC_URL`, `OIDC_ISSUER`, or `ALLOWED_CORS_ORIGIN` or fail closed with `400 INVALID_HOST` (before OIDC discovery or SPA CSP runs), and `app_launch` / OIDC client IP checks use peer-aware `extract_client_ip_for_peer`. `security_headers_middleware` reads only the validated host extension for `200 OK` SPA CSP `connect-src` and skips SPA CSP on non-200 error responses. Both `/api/v1/auth/refresh` and `/api/auth/refresh` mount `auth_rate_limit_middleware` as the outermost layer on a dedicated merged refresh sub-router in `af-api/src/routes.rs` outside `auth_middleware` and `csrf_middleware`, and `AF_DISABLE_RATELIMIT` is ignored under `AETHERFLOW_ENV=production|release`. |

## 3. Trust Boundaries

```text
[Internet / LAN / Tailscale 100.64.0.0/10] ──HTTPS/TLS──> [Apache2 + Subdomain Gateway]
                                   │ (*.aether.local authenticated by default; opt-in AF_ALLOW_UNAUTH_LOCAL_LAN=1 for RFC1918/ULA/link-local only)
                    127.0.0.1:8080 (AetherFlow-Setup;
                    af-api bare default is 0.0.0.0:8080)
                                   ▼
             [aetherflow-api.service (Rust / af-api)]
             (User=aetherflow • ProtectSystem=strict • ProtectHome=read-only • NoNewPrivileges=yes)
                  ├──> [/var/lib/aetherflow/aetherflow.sqlite (0600/0640)]
                  ├──> [/var/lib/aetherflow/mcbrowser/user-<id> (0700)]
                  ├──> [Optional ReadWritePaths: -/srv -/mnt -/media -/data -/opt/AetherFlow/backend/data]
                  ├──> [afpeer0 Tunnel Listener (<tunnel_ip>:9443, SO_BINDTODEVICE, X-AF-{Link,Grant}-Token)]
                  ├──> [/run/aetherflow-transcode/transcode.sock & /run/aetherflow-transcode-worker/worker.sock (SO_PEERCRED)]
                  └──> [/run/aetherflow/runner.sock (0660 root:aetherflow)]
                                   │
                                   ▼
             [aetherflow-runner.service (Root Daemon / af-runner)]
                  ├──> [systemd Service Manager]
                  ├──> [9 Opt-In Declarative Rust Recipes / Locked Bash Package Scripts]
                  ├──> [Peer Clustering Helpers (/v1/peer-{network,storage,transcode}: afpeer0, NFSv4.2, af-transcode-worker.service)]
                  ├──> [aetherflow-self-update-<command>-<channel>-<8hex>.service (af-release)]
                  └──> [aetherflow-plugin-<id>.service (DynamicUser=yes • RO assets/token • 0700 StateDirectory • Inaccessible control-plane & transcode paths • SocketBindDeny=any / SocketBindAllow=<port> • IPAddressDeny=any / IPAddressAllow=localhost)]
```

## 4. Risk Matrix

| Risk | Likelihood | Impact | Severity | Status |
| :--- | :--- | :--- | :--- | :--- |
| Privilege escalation across `runner.sock` | Low | Critical | HIGH | Mitigated (`SO_PEERCRED` + `/proc/<pid>/exe` + strict allowlists + `lstat`/`confined_fs` guards + tracked `af-release::process_group` supervision; Bash installers remain audited privileged paths; `DeclarativeStep::RunCommand` removed) |
| Managed plugin reading/writing API control-plane files, transcode sockets, or `runner.sock` | Low | Critical | HIGH | Mitigated (`af-runner` transient `DynamicUser=yes` units + `InaccessiblePaths` including `/run/aetherflow-transcode*` + read-only `/run/aetherflow-plugin-{app,token}` mounts + fail-closed `503 PLUGIN_ISOLATION_UNAVAILABLE`) |
| Managed plugin reaching sibling host-loopback Marketplace apps (`127.0.0.1:<port>`) | Low | Medium | MEDIUM | Residual boundary (`SocketBindDeny`/`SocketBindAllow` and `IPAddressDeny=any` / `IPAddressAllow=localhost` block unauthorized binds and external/LAN egress, `/metrics` requires `METRICS_BEARER_TOKEN` or active admin session, and `rutorrent` requires `/etc/aetherflow/rutorrent-proxy-token.conf`, but `IPAddressAllow=localhost` still permits loopback TCP connects without `PrivateNetwork=yes`; install only reviewed/trusted plugins) |
| Lateral movement or unauthorized mutation across paired Peer Clustering servers | Low | High | HIGH | Mitigated (dedicated `afpeer0` WireGuard + `SO_BINDTODEVICE` listener, `0640 root:aetherflow` held tokens under `/etc/aetherflow/peers/tokens/`, zero-access-by-default 8-area grants, non-grantable local-only routes, `<< 1 s` revocation teardown, NFSv4.2 pinned to `afpeer0`, `af-transcode-worker.service` `User=jellyfin` + `SO_PEERCRED` + `PrivateNetwork=yes` + secret-free `/etc/aetherflow/transcode.env`; residual blast radius remains for explicit two-way write grants and `sec=sys` NFS exports — see [Peer Clustering](./peer-clustering.md#operational-limits-and-safeguards)) |
| Offboarded admin retaining Subdomain Gateway Basic Auth | Low | High | HIGH | Mitigated (`verify_proxy_basic_credentials` checks live SQLite `users` rows with `role == "admin"` and `totp_enabled == 0` only; `.master.creds` fallback removed; external `rutorrent` routed through Subdomain Gateway; static `htpasswd` limited to custom blocks / `AF_APACHE_LISTEN_ALL=1`) |
| Unauthenticated LAN / Tailscale (`100.64.0.0/10`) access to gateway-protected apps via `Host: <app>.aether.local` | Low | Critical | HIGH | Mitigated (all 10 protected apps require authentication on `*.aether.local` by default, including TOTP `aetherflow_local_app` cookie launch; opt-in `AF_ALLOW_UNAUTH_LOCAL_LAN=1` strictly excludes `100.64.0.0/10` and loopback) |

| Broken update killing the updater mid-restart or drifting system helpers | Low | High | HIGH | Mitigated (dynamic transient `aetherflow-self-update-<command>-<channel>-<8hex>.service` + WAL-safe snapshot + same-FS `0755 root:root` atomic package/helper sync + binary path check + durable receipts) |
| AI prompt injection mutating host state | Medium | High | HIGH | Mitigated (Approval Inbox `pending_actions` gate + `admin_audit_log`) |
| API key, JWT, or TOTP secret plaintext exposure in DB or heap RAM | Low | High | HIGH | Mitigated (AES-256-GCM `enc:v1:` envelope encryption keyed by `AES_MASTER_KEY` + full-capacity `SecretString`/`SecretBytes` volatile zeroization + bounded `ROTATED_TOKEN_GRACE` pruning) |
