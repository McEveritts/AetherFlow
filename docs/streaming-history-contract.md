# Streaming history contract v1

Implementation contract for phases 2–6. The API integration owner owns schema and Rust modules; frontend work consumes `frontend/src/lib/streaming-history.ts` without editing the existing live-dashboard contract.

Authenticated endpoints: `GET /api/v1/auth/streaming/history` and `GET /api/v1/auth/streaming/history/export`. The explorer is independent of the five-second live poll. Query and response fields are declared in the TypeScript contract; Rust uses the same camelCase JSON. Default page size 50, maximum 200; sort `startedDesc` or `startedAsc`, with undated rows last in either order and ID as a unique tie-breaker. Unknown enum/sort/query fields, overlong search/cursors and invalid timezones/dates are errors, not ignored filters.

`window` is `all` by default, a fixed rolling `7d`/`30d`/`90d`/`365d`, local calendar `today`/`month`/`year`, or `custom` with offset-bearing RFC3339 `from` and `until`. Bounds are half-open `[from, until)` in UTC. Calendar windows use the IANA `timezone` (default UTC); DST changes are resolved at local calendar boundaries. Dated windows exclude undated rows; all-time retains them. SQL timestamps are interpreted as UTC, not host-local time. Search is literal, ASCII-case-insensitive, with Unicode characters matched literally; wildcard characters do not broaden a query. IP addresses, device IDs and session keys are never searchable.

Existing rows default to `legacy_unverified`, never inferred observed sessions based only on session-key shape. New collectors explicitly write `observed_session` or `item_summary`; real event imports use `imported_event` and stable upstream IDs. Only included observed/imported events count as confirmed plays/watch time/estimated transfer. Summaries and legacy records remain separately inspectable. Missing values remain null; zero is only emitted when actually recorded. Estimated bytes are not network measurements. The current dashboard remains a backward-compatible legacy response until its metrics can consume the same contract without mislabeling old totals.

Admin scope can inspect all providers and excluded raw records. Non-admin scope contains only provider users explicitly linked to the authenticated AetherFlow user in `streaming_user_links`; no link means no history. Counts/facets/exports share that predicate. Non-admin rows omit IP addresses and device IDs. Links are explicit identity mappings, never guessed from display names.

Snapshots freeze the maximum inserted ID and rolling/calendar reference instant. Signed, viewer/query-bound cursor tokens expire after fifteen minutes. Inserts above the watermark are excluded. Mutation/deletion of existing evidence, policy changes or identity/label changes invalidate the snapshot with HTTP 409: restart the query; do not silently append to old pages. Page responses return `scope.snapshotToken` for full-query export at the same snapshot. Export removes `cursor` and sends that token as `snapshot`; it exports the full query, not just the current page. Read batches release the single pooled connection; timeout/cancellation/mutation must fail rather than silently deliver an incomplete successful CSV. Available records means authorized policy-visible archive size before optional query filters; matching records means the complete filtered cohort, not the loaded page.

Migration 20 is additive and transactional, retains every legacy record/field, and requires a consistent, integrity-checked SQLite backup in a private directory before a file-backed database is migrated. In-memory tests need no disk backup. Production deployment and applying destructive reconciliation remain separately authorized actions.

## Collection and Identity

The fifteen-second collector records point samples separately from interval estimates. The first observation of a playback accrues zero seconds/bytes because its preceding interval is unknown. Reconnect gaps, missing observations over sixty seconds, and nonpositive dashboard intervals cannot add watch time or estimated transfer. Distinct provider/server/session/play-session/item generations preserve repeat plays; polling cannot distinguish a stop/restart entirely between observations when every identifier remains unchanged.

Item-summary sync uses a provider-instance-scoped key, never promotes a legacy row, and may upgrade timestamp certainty only when the upstream payload actually supplies a parsed `LastPlayedDate`. A replacement server does not overwrite an earlier instance's summaries. Legacy dashboard statistics remain explicitly mixed/unverified, not confirmed-play totals.

Before either provider collector records observations, it verifies `/System/Info/Public`, establishes a missing configured server identity, and rejects an unexpected replacement identity. Jellyfin active session `ServerId` must also match. The write transaction rechecks the enabled provider URL and server identity, so a configuration change between fetch and persistence cannot relabel observations. ASCII case differences are accepted for upstream identity comparison while stored server-ID casing is preserved.

### Provider Item Metadata

Library and genre enrichment is asynchronous and restricted to matching verified observed-session evidence. Imports, item summaries and legacy rows are not rewritten. Library labels require collection-root/ancestor evidence; arbitrary virtual views and aggregate folders are not invented libraries. Missing/deleted upstream metadata preserves existing labels. Failed media-folder/ancestor requests are not cached as successful empty results; cached item failures preserve their actual error type/status.

Each provider has a single cancellable background refresh, at most 32 distinct items, six seconds per request, 2 MiB per response and a thirty-second network budget. Successful item/root metadata is cached for ten minutes; item failures for two minutes. HTTP work holds no SQLite connection, and configuration resolution/persistence run in blocking tasks. Background persistence considers only observations seen within ten minutes, including recently completed plays; it does not backfill all old plays on each telemetry tick. The explicit persistence helper can process older matching observations. Unchanged labels do not execute writes or churn snapshot revisions.

Identity probing deliberately remains fresh rather than using a ten-minute identity cache. HTTP provider URLs remain supported for local/native installations; non-loopback cleartext HTTP exposes credentials to network observers. Use HTTPS for remote providers or a trusted encrypted transport. Redirects and the shared URL validator's blocked targets remain disallowed. Mock HTTP acceptance does not establish real-provider authentication, ancestor hierarchy or playback behavior.

## Administrative Import and Reconciliation

Administrative endpoints live under `/api/v1/admin/streaming/`. Event import accepts at most 500 events per batch. A stable upstream `sourceEventId` is namespaced by provider, server, and `source` before persistence; the response echoes the original source ID. Source names must remain stable across retries. `expectedCheckpoint` is omitted/null for the initial batch and must match the last committed checkpoint when advancing. Retrying the current checkpoint permits only already persisted event IDs; fresh IDs require a new checkpoint. An earlier delayed batch cannot rewind a newer checkpoint, and rejected mixed retry/new batches roll back atomically. Cross-source overlaps are conservatively ambiguous even with a zero reconnect window, rather than counted twice as confirmed plays. Stock item summaries and activity logs are not real event imports; direct upstream event fetching remains unavailable.

Reconciliation previews are read-only, and every heuristic classification is explicitly a **suspected, unverified proposal**. A `:sync:` key, an epoch-looking date, or a numerical default alone is not proof of fabricated data. Operators must independently verify source evidence before approving the exact proposed changes. Existing timestamps are not upgraded to `last_played` based on a key shape, and today's configured server ID is never assigned to unknown historical rows. Approval binds the actor, exact row fingerprints, revision and archive row count, including insert-only drift. A verified consistent backup precedes an immediate write transaction and revalidation; stale, unauthorized, expired, empty or mismatched approval cannot mutate history. No production reconciliation is performed by building or testing the implementation.

## Portability and Operational Limits

Version 1 portability is a whitelisted JSON format, capped at 8 MiB and 10,000 total portable records. Provider credentials, IPs and device identifiers/names are omitted. Export, preview and restore are admin-only; merge/replace restore and reconciliation require a separate exact-preview approval and a verified on-disk backup, never an absent in-memory backup. Merge resolves history by stable session/event identity and remaps occupied instance-local row IDs along with label/sample parent links. It preserves target tracking policy and reports conflicting bandwidth sample IDs rather than overwriting them. Browser archive downloads remain compact and enforce the same restore size limit. Large archives require narrowing or a future chunked format—there is no claim of unlimited backup size. Preview tokens and cursor signing state are process-local; restart invalidates outstanding approvals/cursors, and multi-process use requires shared state or sticky routing.

Browser CSV downloads are capped at 128 MiB; server export uses independent 1,000-row internal batches and a thirty-second deadline. Bookmarks persist durable filters, not expiring viewer-bound cursor tokens. Existing evidence updates—including active watch/byte estimates—can invalidate archive snapshots with HTTP 409; restarting is required rather than mixing counts and rows from different evidence revisions. Real Jellyfin/Emby client and browser acceptance remain separate release gates; Emby stays coming-soon until those checks pass.
