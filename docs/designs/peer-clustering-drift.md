- **Document role:** Companion preflight audit and integration decision log to [peer-clustering.md](peer-clustering.md). Peer Clustering replaces AetherFlow's legacy single-master clustering with WireGuard-backed peer links (`afpeer0`), scoped management grants, an HTTP/WebSocket management proxy with UI server switching, NFSv4.2 media sharing, and Rust-native Jellyfin transcode offloading. Architectural framing—[The Problem](peer-clustering.md#the-problem), [Goals](peer-clustering.md#goals), [Non-Goals](peer-clustering.md#non-goals), [Technical Plan (Architecture)](peer-clustering.md#technical-plan-architecture), [Alternatives Considered](peer-clustering.md#alternatives-considered), [Risks & Mitigations](peer-clustering.md#risks--mitigations), [Terminology and system context](peer-clustering.md#terminology-and-system-context) (defining `McBrowser`, `FileShare`, `MediaFlow`, `Plugin Sandbox`, and `AreaFence`), and full SQL/wire schemas ([Data model](peer-clustering.md#data-model-migrations-2527-in-af-db), [Wire and IPC contract summary](peer-clustering.md#wire-and-ipc-contract-summary))—lives in [peer-clustering.md](peer-clustering.md). For baseline AetherFlow control-plane/runner architecture (`af-api` unprivileged HTTP/WS daemon talking to root `af-runner` over `/run/aetherflow/runner.sock`, Marketplace, and systemd sandboxing), see [docs/architecture.md](../architecture.md).

### Ten-phase decisions

| Phase | Decision | Technical rationale | Rejected alternatives |
| :--- | :--- | :--- | :--- |
| P7 and P9 | Target Jellyfin 12.4 on both servers and require matching `jellyfin-ffmpeg` package versions without apt pinning. | Matches Server A's Debian 13 (`12.4+deb13` / `jellyfin-ffmpeg8 8.1.3-1-trixie`) apt state and avoids stale security-pinned Debian packages. *(Note: `config/package_automation.json:23`—AetherFlow's apt/sandbox package automation manifest—targets `jellyfin`, whose Debian dependency on `jellyfin-ffmpeg*` uses `>=`, so standalone `jellyfin-ffmpeg` point-release drift requires explicit `jellyfin-ffmpeg*` alignment if observed on Server B.)* | Apt version pinning (blocks security updates and drifts across Debian point releases); cross-version `ffmpeg` flag translation (fragile across filter/encoder revisions). |
| P0, P4, P5 | Ship Migrations **25** (peer tables in P0), **26** (drop legacy `cluster_*` tables in P4), and **27** (`peer_received_grants`, `peer_grant_epochs`, `peer_received_grant_cleanups` in P5). Keep link hash in `peer_links` and independent grant digest in `peer_grants`. | P3 pairs and checks health before grants exist; P5 grant revocation preserves link health and orders concurrent rotations via monotonic `generation` counters across restarts. | Single link-only bearer token (couples management revocation to link health); retroactive squashing of P0–P5 commits mid-flight (breaks per-phase incremental rollback/verification). |
| P3 | Encode WireGuard peer ownership in 10 internal `peer_links.state` values projected to 4 public API states via `public_link_state`. | Preserves Migration 25's schema while enforcing an affirmative `is_wg_peer_owned` allowlist before destructive `RemovePeer` (preventing removal of an externally managed or unconfirmed WireGuard peer). | Adding a separate `wg_peer_owned INTEGER` column via another migration (explicit boolean column vs. an extra migration; tracked in the post-release simplification backlog below). |
| P0, P3, P5, P7, P9, Bundles B–C | Progress `GET /health` capabilities incrementally (served on both public `GET /health` and the link-authenticated tunnel listener's literal `GET /health` path on `:9443`, not `/peer/v1/health`): `[]` (P0) → `["links"]` (P3) → `["links", "grants"]` (P5) → `["links", "grants", "storage"]` (P7) → `["links", "grants", "storage", "transcode"]` (P9). In Bundle B(d) & C, public `GET /health` returns `"transcode": null` unconditionally while link-authenticated tunnel `GET /health` serves cached `"transcode"` capabilities (with `worker_max_jobs`) plus `"inbound_grant_generation"`. | Allows mixed-version peers to negotiate `Compatible` / `Limited` / `Incompatible` states without false capability claims, prevents unauthenticated host FFmpeg/GPU inventory disclosure on public `/health`, enables controller worker-cap auto-clamping, and reconciles offline grant revocations on link recovery. | Advertising all capabilities from P0 or bumping `peer_protocol` per phase; exposing cached hardware/FFmpeg metadata on unauthenticated public `/health`. |
| P1 and P6 | Use thread-local `std::cell::RefCell` state in Leptos-free `af-web-core` driven by `af-web-app`'s reactive `active_server_id` signal (`state.rs:109`) in P6. Start from P1's telemetry WebSocket (`BrowserConnection`) and add `LogStreamConnection` in P6. | Keeps `af-web-core` free of Leptos dependencies while giving every tab transparent `/api/v1/peers/{id}/...` prefixing and epoch-fenced live logs. | Passing explicit target-bound `LocalApiClient`/`ScopedApiClient` handles to every tab call site (larger signature/DI refactor across existing WASM API helpers, though P6 still touched tab views to wire `AreaFence`). |
| P2–P4 | Land dormant runner in P2, tunnel listener + attempt-bound hello exchange in P3, then retire legacy `cluster_daemon` and `cluster_*` tables with Migration 26 in P4. | Keeps the existing Cluster UI functional until P3's replacement tunnel/pairing backend is verified, then deletes the legacy subsystem in a single cutover. | Deleting legacy `cluster_daemon` in P0 (leaves the Cluster tab broken across P0–P3). |
| P5–P6 | Verify independent link and grant credentials in P5 before enabling managing-server HTTP/WS proxying and browser server switching in P6. | Enforces fail-closed target authorization before exposing browser proxy paths while preserving link health after grant revocation. | Enabling proxy routing before `TrackedRouter` scope classification (risks exposing unclassified admin routes). |
| P7 | Stop peer media NFS mounts on the first failing health tick when a WireGuard peer is removed or its handshake is stale (`> 180 s`); require two consecutive sentinel probe failures (5-second probe timeout on the 15-second health loop) for transient NFS errors. | Targets the 30-second mount-stop acceptance goal on explicit peer removal (15 s tick + immediate `StopMount`, up to ~45 s worst case under `TimeoutSec=30` active I/O) without flapping on single transient probe glitches. On a silent crash/hung NFS with 1 mount, each tick takes `5 s /health + 5 s ProbeSentinel = 10 s < 15 s` (no `MissedTickBehavior::Delay` tick slip), so two ticks take ~25–40 s before `StopMount` starts (plus up to 30 s `StopMount`); `MissedTickBehavior::Delay` (`health.rs:119`) adds drift once sequential probes exceed 15 s (≥ 2 hung mounts or ≥ 2 dead peers, plus cross-link `StopMount` head-of-line blocking). This silent-crash overrun vs. the 30 s explicit-removal goal is an accepted initial limitation until health/sentinel probing is parallelized (see backlog below); live NFSv4.2 timing remains pending Server B acceptance. | Stopping on a single sentinel failure (flaps under brief I/O spikes); waiting for WireGuard stale timeout alone (180 s exceeds the 30 s target). |
| P8–P9, Bundles A–B | Build `af-transcode` using `wincode 0.6.3` (bincode-v1 LE layout) and bundle `bin/af-transcode` in release archives; relay frames over a custom RFC 6455 WebSocket client (`peers/transcode.rs`) enforcing first-byte no-duplicate fallback (`WsWriteError::BeforeAnyBytesSent`) on worker submission; use deterministic debounced `ScheduleApiRestart` (`systemd-run --unit=aetherflow-transcode-api-restart --on-active=1s`) when creating `aetherflow-api.service.d/20-aetherflow-transcode.conf` or when live `ProtectSystem=strict` / missing `jellyfin` GID blocks socket access; and provision secret-free `/etc/aetherflow/transcode.env` (`0640 root:jellyfin`) loaded via `EnvironmentFile=-/etc/aetherflow/transcode.env` across all 4 consuming units (`af-transcode-worker`, `jellyfin`, `aetherflow-api`, `aetherflow-runner`). | Replaces `bincode` (rejected by `cargo deny` under `RUSTSEC-2025-0141`) with maintained bincode-v1 binary framing and bounded pre-allocation, enforces exact byte-level fallback accounting on the bound tunnel socket to prevent simultaneous local and remote encodes, activates `20-aetherflow-transcode.conf` (`SupplementaryGroups=jellyfin`) without duplicate transient timers or manual SSH restarts, and shares `AF_TRANSCODE_REAL_FFMPEG` / `AF_TRANSCODE_WORKER_MAX_JOBS` safely without ever exposing `/etc/aetherflow/aetherflow.env` secrets to `User=jellyfin`. | `serde_json` framing (base64 overhead on raw stdio media chunks); `tokio-tungstenite` client wrapper over a byte-counting stream (deferred to post-release backlog); loading `aetherflow.env` inside `af-transcode-worker.service` (leaks `AES_MASTER_KEY`/`JWT_SECRET` to `User=jellyfin`). |

### Phase P8: Local transcode foundation

Full transcoding architecture, controller (Jellyfin server running the dispatcher inside `af-api`) vs. worker (`af-transcode-worker.service` running remote `ffmpeg`) roles, and socket flows live in [peer-clustering.md (Rust-native transcode dispatcher)](peer-clustering.md#rust-native-transcode-dispatcher):

- **Wire codec (`wincode 0.6.3`):** Replaced `bincode` (`RUSTSEC-2025-0141`) with `wincode = { version = "0.6.3", features = ["derive"] }` preserving bincode-v1 little-endian fixed-int layout, 4-byte BE length prefix, 1 MiB `MAX_FRAME_BYTES` pre-deserialization cap, trailing-byte rejection, structural caps (`MAX_START_ARGS = 512`, `MAX_START_ARG_BYTES = 64 KiB`), and 10-variant `Frame` (`0..=9`, adding `Frame::StdinEof` at discriminant `4`).
- **Handshake, probe vs. capability modes, worker protocol confinement, and fallback boundaries:**
  - The `af-transcode` binary supports three modes (`shim`, `worker`, and `capabilities` probe CLI). In `shim` mode, `AF_TRANSCODE_SHIM_ACTIVE` refuses recursive invocation with exit code `1`; `ffmpeg` probe calls (`is_probe`: `-version`, `-encoders`, no `-i`, etc.) and non-UTF-8 Unix arguments `exec` local `ffmpeg` directly.
  - In Bundle B(d), `argv.rs` defines `WORKER_LOCAL_PROTOCOL_WHITELIST` (`"file,pipe,fd,crypto,data,subfile"`, `argv.rs:88`), `has_network_input` (`argv.rs:1373`), and `validate_worker_args` (`argv.rs:1493`). The controller dispatcher immediately returns `Frame::RunLocal` for network-protocol inputs or non-local protocol whitelists (`peers/transcode.rs:4554`), while `worker.rs` (`L588,684`) independently rejects network inputs/widened whitelists, injects `-protocol_whitelist file,pipe,fd,crypto,data,subfile`, and clamps child `cwd` via `resolve_worker_child_cwd` (`config.rs:658`).
  - On the shim → controller `af-api` dispatcher Unix socket (`transcode.sock`, `shim.rs:273-278, 357-389`), local fallback runs on any write error/timeout **before all bytes** of `Frame::Start` are written; after submission completes, only an explicit `Frame::RunLocal` authorizes local fallback, and stream loss exits non-zero without starting a duplicate local encode. In P9, the controller `af-api` dispatcher enforces the stricter first-byte `WsWriteError::BeforeAnyBytesSent` boundary when sending `Frame::Start` over `/peer/v1/transcode/jobs` to worker `af-api` (`peers/transcode.rs:1728-1826`; pre-first-byte failures retry another worker or return `RunLocal`, while post-first-byte drops/rejections exit non-zero without duplicate local execution), after which worker `af-api` relays frames to local `worker.sock`.
  - `RECOMMENDED_DISPATCHER_REMOTE_START_TIMEOUT = 1,500 ms` sits inside the shim's `2,000 ms` budget (`DEFAULT_HANDSHAKE_TIMEOUT`). `af-hardware::detect_render_nodes()` exposes deterministic render-node ordering while preserving legacy GPU selection order. `TranscodeCapabilities` (`capabilities.rs:51-66`) advertises optional `worker_max_jobs` (`Some(configured_worker_max_jobs())`, Bundle B(b)).
- **Runtime socket paths (wired in Phase P9):** Dispatcher defaults to `/run/aetherflow-transcode/transcode.sock` and worker defaults to `/run/aetherflow-transcode-worker/worker.sock`, keeping `/run/aetherflow` exclusive to `af-runner` and keeping `jellyfin` outside group `aetherflow`.
