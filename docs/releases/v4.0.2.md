# AetherFlow v4.0.2

*Released November 28, 2026. Upgrades from v4.0.1 and is available on both the stable and nightly channels.*

Most of this release is security hardening. Secrets are scrubbed from logs more thoroughly and wiped from memory when no longer needed. Privileged commands can no longer run without limits. Root no longer follows a service's symlinks into files it shouldn't touch.

Alongside that, distributed Jellyfin transcoding now picks workers based on what their GPUs can actually do and how busy they are. The Overview page has a new service topology map, and several marketplace apps install cleanly on Debian 13 again. Stable and nightly are back on the same code.

There are no breaking API or CLI changes, and the one database migration runs automatically. Some of the new checks are stricter than before, though, and a few of them can stop a service from starting. Read [Before you upgrade](#before-you-upgrade) first. It takes a few minutes.

## Before you upgrade

Check these five things on any existing install.

**`JWT_SECRET` must be at least 32 bytes.** If it is shorter after trimming whitespace, or contains tabs, line breaks or other control characters, the API will refuse to start. To generate a valid one:

```bash
openssl rand -hex 32
```

**Release config files are checked strictly.** A file passed to `af release --config`, usually `release-manager.conf`, must meet all of these:

- a regular file, not a symlink;
- owned by root;
- not group- or world-writable;
- 64 KiB or smaller.

Only the 31 allowlisted keys are read. GitHub tokens and `AETHERFLOW_SKIP_PROVENANCE_VERIFY` are no longer read from this file. Move them to the environment or to `/etc/aetherflow/aetherflow.env`.

**Plugins must be owned by root.** In production, the plugins directory, every plugin inside it and every `plugin.manifest.json` must be owned by root. None of them may be writable by a non-root group. Manifests are capped at 256 KiB. Check any plugins you added yourself, and the directory in `AETHERFLOW_PLUGINS_DIR` if you set one:

```bash
sudo chown -R root:root /path/to/plugins
sudo chmod -R go-w /path/to/plugins
```

**The transcode worker only accepts known callers.** Its socket now accepts connections only from the worker's own user, root and `aetherflow`. If something else needs to connect, list its user names or UIDs in `AF_TRANSCODE_ALLOWED_PEER_UIDS` in `/etc/aetherflow/transcode.env`.

**Forwarded headers are only trusted from known proxies.** AetherFlow now drops `X-Forwarded-*`, `Forwarded` and `X-Real-IP` from any peer not listed in `TRUSTED_PROXIES`. If a reverse proxy on another machine sits in front of AetherFlow, add it to `TRUSTED_PROXIES`. Otherwise every request will appear to come from the proxy.

## What's new

### Transcoding that knows the hardware

Transcode workers used to advertise every encoder their FFmpeg build included, whether or not the GPU could run it. Now, when `vainfo` is installed, a worker probes each render node and advertises only the encode and decode profiles the hardware really supports. The Cluster page marks these workers **Silicon verified**. Jobs that still use VA-API tone-mapping (`tonemap_vaapi`) go only to Intel GPUs.

Choosing a worker now takes its current load into account. The dispatcher weighs each worker's configured weight, free job slots, current CPU and GPU load, and round-trip time over the tunnel. Idle workers on the LAN with no load data still split jobs by the weights you set.

You can also decide how much work the controller keeps for itself. Under **Cluster → Jellyfin transcoding**, two new settings appear:

- **Dispatch policy:** `remote_first` (the default), `local_first` or `balanced`.
- **Local max jobs:** a cap of 1 to 64 transcodes on the controller.

Vulkan support is now split in two:

- **Vulkan Compute** handles HDR tone-mapping through libplacebo and is on by default. With `AF_TRANSCODE_OPTIMIZE_VULKAN_TONEMAP=true`, VA-API tone-mapping is rewritten to use it, and those jobs go only to workers with a real Vulkan Compute device.
- **Vulkan Video** handles hardware decode and encode, and stays off unless you set `AF_TRANSCODE_VULKAN_VIDEO=true`.

A software renderer such as llvmpipe doesn't count as Vulkan support for either one.

Two new tuning options are available:

- `AF_TRANSCODE_ADAPT_BACKEND` (`off`, `gpu`, `prefer_qsv` or `all`) lets a worker adapt jobs to the GPU it actually has.
- `AF_TRANSCODE_FFMPEG_THREADS` caps FFmpeg's thread count.

The worker service also gets a 512 MiB shader cache that persists between jobs, and on AMD, access to `/dev/kfd`. The Cluster page now shows each worker's CPU, GPU and latency figures, its hardware decoders, and how many jobs are running locally.

### A service topology map

**Overview → Service health** now draws your services as a map. It has three columns: gateways such as Apache, nginx, Caddy, Traefik and HAProxy, then your services, then what they depend on, such as databases and the runner. Curved, labelled links (Core, Socket, Proxy, Direct, Two-way) show how each service is reached.

You can:

- search for a service to highlight it;
- zoom from 0.4× to 3× with the buttons or the scroll wheel;
- drag to pan, and reset the view;
- switch between the map and a list.

A legend explains the link types. Clicking a service opens an inspector that lists its incoming and outgoing connections, each clickable, along with its raw JSON. The map is translated into all six supported languages.

### Security hardening

Most of this release's work went here. None of it changes how you use AetherFlow day to day. It is about keeping a misbehaving service away from root-owned data, and keeping secrets out of places they shouldn't be.

**Secrets stay out of logs.** The redaction applied to diagnostics, job output and lifecycle history has been rewritten. It now catches credentials in:

- curl arguments;
- quoted and escaped strings;
- Basic, Bearer and Digest auth headers;
- cookies;
- URLs with embedded passwords;
- headers that span several lines.

JSON is scrubbed by its structure, not by pattern matching. History saved by older versions is scrubbed again when it's read. Expect more `[REDACTED]` markers than before.

**Secrets are wiped from memory.** The following keys and secrets are now held in types that zero their memory when released and never show up in debug output:

- the JWT signing key;
- the AES master key;
- OIDC keys;
- peer and WireGuard secrets;
- plugin signing keys.

**Privileged commands have limits.** Every command the runner or release manager starts as root now runs in its own process group, with a timeout and an output cap. If it overruns or is cancelled, the whole group is killed. Legacy Bash installers get one hour and 64 MiB of output.

**Root doesn't follow a service's symlinks.** When AetherFlow reads or backs up a database that belongs to a service, such as an *arr database, it doesn't follow symlinks, and it opens the file with that service user's permissions instead of root's. Databases in directories the service owns are copied into a private, root-only location before they are snapshotted. That copy is limited to 2 GiB.

**Tighter inputs.** Release config files and plugins must now be owned by root, as described above. Release archives have size limits. The dashboard checks that a message from a plugin really comes from that plugin's frame.

**Release publishing.** Releases are published from a protected GitHub environment, and the pipeline refuses to publish under any account but the project owner's. Archives are packed deterministically.

### Marketplace and ingress fixes

- Removing an app now also removes the Apache sites AetherFlow created for it (`aetherflow-app-<app>.conf`, `aetherflow-ext-<app>.conf` and the matching `-le-ssl.conf`). Older `<app>.conf` files are left alone.
- An app whose site was waiting for a TLS certificate switches to HTTPS automatically once a certificate covering its domain is issued. Certificate sync triggers this through the new runner route `POST /v1/ingress/resync-tls`.
- Install, update and remove no longer fail on the usual `sites-enabled` → `sites-available` symlinks for AetherFlow's own sites. Symlinks that point anywhere else are still refused. Rolling back now reloads Apache reliably.
- After every successful install, update or removal, AetherFlow rebuilds its hosts and DNS-provider files from the database, so they always match what's installed.
- An app you just updated or removed no longer shows a stale "update available". If AetherFlow can't read an app's installed version, it now says "Installed version could not be confirmed" instead of showing raw error output.

### Shared media and sandboxes

Each app's systemd sandbox settings now live in one file, `/etc/systemd/system/<unit>.d/10-aetherflow-sandbox.conf`. The old unnumbered `aetherflow-sandbox.conf` is removed, so your own overrides in `20-*.conf` through `99-*.conf` win.

Thirty-two families of media servers, download clients and *arr apps now run with `UMask=0002` instead of `0077`. That includes qBittorrent, Deluge, rTorrent, Transmission, SABnzbd, NZBGet, Sonarr, Radarr, Lidarr, Readarr, Bazarr, Jellyfin, Plex, Emby, Audiobookshelf, Kavita and Navidrome. Files these apps create are readable and writable by their group. That lets shared libraries and hardlinks work across local disks and peer NFS mounts. Apps that don't share media keep `0077`.

AetherFlow also warns when a writable peer NFS export or mount uses a group ID between 1 and 999. Those IDs are assigned separately on each machine, so the same number can mean a different group on each peer. The warning appears in the API log, the audit trail, `af cluster diagnose` and the Cluster Storage page.

### Debian 13 installer fixes

These apps failed or rolled back on a fresh Debian 13 (trixie) install, and now install cleanly:

- **Autobrr:** health checks use the readiness endpoint. The old one returned 404, which rolled the install back.
- **Gitea:** its secrets are generated before the first database migration.
- **Jellyseerr:** a fresh install no longer aborts trying to stop a service that hasn't been loaded yet.
- **KasmVNC:** status checks work under OpenSSL 3.5, where curl exits with code 56 when KasmVNC closes the connection, even after a valid response.
- **Kavita:** starts from a seeded config with the configured port, localhost binding and a generated token key.
- **Nextcloud:** picks a supported PHP version (8.4, then 8.5, then 8.3, never the experimental 8.6) and runs it through PHP-FPM, which works with Apache's event MPM.
- **Scrutiny:** installs its own InfluxDB 2.7.12 as `scrutiny-influxdb.service` on `127.0.0.1:8086`, along with the web frontend.

The Calibre-Web, SABnzbd, Palate, Dispatcharr, Piped and Invidious installers now build and run their setup steps in clean, isolated environments. Dispatcharr's admin credentials are passed over stdin instead of the environment. A failed install no longer tries to disable services that were never created when it rolls back.

### Other changes

- Setup now takes a lock at `/run/aetherflow-setup.lock`, so two runs can't overlap. It needs `flock` and now also installs `ed` and `libapache2-mod-fcgid`.
- Deploy and rollback keep `/opt/AetherFlow/packages/` and `/usr/local/bin/AetherFlow/` in exact step with the release, and remove anything that isn't part of it. The retired `/usr/bin/af-heal` is removed.

## What changes after you upgrade

- **HDR tone-mapping uses Vulkan Compute by default.** To keep v4.0.1's VA-API tone-mapping, set `AF_TRANSCODE_OPTIMIZE_VULKAN_TONEMAP=false` in `/etc/aetherflow/transcode.env`.
- **Vulkan Video jobs stay local.** Jobs that use `*_vulkan` encoders or `-hwaccel vulkan` are no longer sent to workers unless you set `AF_TRANSCODE_VULKAN_VIDEO=true`.
- **Some changes need one more step to take effect.**
  - The shader cache and `/dev/kfd` access arrive when the worker service is rewritten. Open **Cluster → Jellyfin transcoding** and save with the worker enabled.
  - The new sandbox file and umask arrive the next time an app is reinstalled or updated. To apply them sooner, run `sudo af sandbox apply <app>` and restart that service. After that, files the app creates without an explicit mode are `0664`, and directories are `0775`.
- **Removing an app removes its Apache sites.**
- **The helper directories are pruned on deploy and rollback.** Keep any customizations somewhere else.
- **New limits.** Legacy installers are stopped after one hour or 64 MiB of output. Root snapshots of a database in a service-owned directory fail if the database and its WAL and journal files add up to more than 2 GiB.
- **More `[REDACTED]` in diagnostics.** This is intended.

## Upgrading

If you want a restore point, take a backup first, either from **Settings → Backups & Restore** or with `sudo af backup create`.

Then deploy from **Settings → System Updates**, or from the command line:

```bash
sudo af release deploy --channel stable    # or: --channel nightly
```

If the runner isn't reachable, `sudo af release deploy --local --channel stable` runs the deploy directly.

If the new release fails its health check after the switch, AetherFlow rolls back to the previous release on its own. To roll back by hand, run `sudo af release rollback --local`.

Upgrading from v3.2.x? Read the [v4.0.0 upgrade guide](./v4.0.0.md#breaking-changes--upgrade-guide) and [Upgrading & Rollbacks](../upgrading.md) first.
