# AetherFlow v4.0.2

**Released:** November 28, 2026 · **Tag:** `v4.0.2` · **Base:** `v4.0.1` (`e98cc767`) · **Channels:** `stable` (`master`) & `nightly`

AetherFlow v4.0.2 brings `master` and `nightly` back together. It combines the post-v4.0.1 **Wave 0–2 security hardening program** with the post-v4.0.1 **nightly feature and reliability work**:

- **Security hardening:** a rewritten diagnostic redaction engine, zeroized in-memory secrets, process-group-bounded subprocesses, `O_NOFOLLOW`/dirfd filesystem confinement, a strict release-config allowlist, root-owned plugin trees, and release publishing authored by `McEveritts`.
- **Distributed transcoding:** silicon-accurate GPU probing, load- and latency-aware dispatch with selectable dispatch policies, backend adaptation, and Vulkan Compute HDR tone-mapping kept separate from Vulkan Video codecs.
- **Overview:** a redesigned tiered **service topology map**.
- **Marketplace:** Apache ingress and lifecycle fixes, a canonical systemd sandbox drop-in with group-shared media `UMask`, and Debian 13 installer fixes for eight apps.

**By the numbers (`v4.0.1...v4.0.2`):**
- 23 commits (22 non-merge).
- 236 files changed (+99,888 / −6,835 lines).
- 1 new SQLite migration (28).
- 8 new transcode environment variables.
- 1 new runner route.
- 272 new Rust tests and 21 new Python tests.

## Highlights

- **Wave 0–2 security hardening:**
  - Rewrites diagnostic and lifecycle secret redaction as a linear-time, UTF-8-safe state machine.
  - Wipes JWT, AES, OIDC, peer, WireGuard, and plugin signing secrets from memory on drop (`SecretString`/`SecretBytes`).
  - Bounds every privileged subprocess by process group, output size, and timeout.
  - Confines root-side SQLite, lease, and snapshot I/O with `O_NOFOLLOW`/dirfd and per-thread `fsuid` switching.
  - Locks the release config down to a 31-key allowlist and requires root-owned plugin trees.
- **Smarter distributed Jellyfin transcoding:**
  - Probes real VA-API encode/decode profiles (`vainfo`) and Vulkan devices on each worker.
  - Scores workers by weight, free slots, live CPU/GPU load, and tunnel RTT.
  - Adds `remote_first` / `local_first` / `balanced` dispatch policies with a local job cap.
  - Adapts backends across GPU vendors.
  - Tunes FFmpeg threads and adds a persistent Mesa shader cache.
  - Turns on Vulkan Compute (libplacebo) HDR tone-mapping by default, while keeping it independent from opt-in Vulkan Video codecs.
- **Redesigned service topology map:**
  - Shows Overview → Service health as a three-tier Gateway → Service → Dependency map, with status cards and curved, labelled links.
  - Adds search highlighting, zoom and pan, a legend, a Map/List switcher, and a richer Service inspector.
- **Marketplace ingress & lifecycle correctness:**
  - Snapshots now accept managed Apache `sites-enabled` symlinks.
  - Removing a package deletes its managed `aetherflow-*` vhosts.
  - Vhosts left in the TLS-pending state upgrade automatically once a certificate covers their domain (`POST /v1/ingress/resync-tls`).
- **Sandbox & peer storage alignment:**
  - Writes a single canonical `10-aetherflow-sandbox.conf` drop-in, so operator `20-*`…`99-*` overrides win.
  - Media servers, downloaders, and `*arr` services get `UMask=0002` for group-shared and peer NFS media.
  - Warns about writable peer NFS exports or mounts that use host-local dynamic system GIDs.
- **Debian 13 (`trixie`) installer fixes:**
  - Fixes fresh installs of Gitea, Jellyseerr, KasmVNC, Kavita, Nextcloud, Scrutiny (now with standalone InfluxDB 2.7.12), and Autobrr.
  - Hardens Calibre-Web, SABnzbd, Palate, Dispatcharr, Invidious, and Piped installers with isolated build environments and secret handling.
- **Release pipeline integrity:**
  - Publishes nightly and stable releases from a protected `release-publish` environment, under a PAT verified as `McEveritts`.
  - Caps worst-case Actions concurrency at 18 jobs.
  - Produces deterministic GNU tar archives.
  - Keeps tool-specific review artifacts out of every shipped archive.

## Detailed Changes Since v4.0.1

### 1. Wave 0–2 Security & Privilege-Boundary Hardening (`master`)

#### Diagnostic & Lifecycle Secret Redaction (`95783e10`, Wave 1A)

- **Rewritten redaction engine ([`backend-rs/crates/af-models/src/secret_redaction.rs`](../../backend-rs/crates/af-models/src/secret_redaction.rs)):** `redact_diagnostic` is now a line-classifier state machine that tracks context across lines. It covers:
  - curl arguments: `-u`/`--user`, `--proxy-user`, `--cert`/`--proxy-cert` including passphrases, and attached and bundled short flags;
  - quoting: shell, `\uXXXX`-escaped, and ANSI-C `$'…'` quotes;
  - Basic, Bearer, and Digest auth schemes, cookies, and URL userinfo;
  - header folding and continuations, and nested containers.

  It also preserves `\r\n`/`\r` line endings.
- **New sensitive key terms:** `signing_key`, `encryption_key`, `master_key`, bare `auth`, and ALL-CAPS `*_KEY` names.
- **Structural JSON scrubbing:**
  - `redact_secrets` walks valid JSON up to depth 16, under a shared byte budget clamped to 64 KiB–32 MiB.
  - JSON with duplicate keys is re-serialized, so a secret cannot hide behind a shadowed key.
  - New entry points: `redact_secrets_with_budget`, `redact_secrets_flat`, `redact_url_credentials`, and `redact_auth_scheme_credentials`.
- **Persisted lifecycle sanitization ([`af-release/src/lifecycle/jobs.rs`](../../backend-rs/crates/af-release/src/lifecycle/jobs.rs)):**
  - `sanitize_persisted_text` runs on every stored job and history field.
  - `get_lifecycle_history` re-sanitizes legacy rows on read.
  - The in-memory job registry (`af-services/src/package_jobs.rs`) sanitizes snapshots and outcomes, and redacts before parsing diagnostic markers.
- **Tests:** about 70 new UTF-8 boundary, no-panic, idempotency, and linear-time scaling regressions across `af-models`, `af-release`, `af-runner`, and `af-services`.

#### Secret Zeroization, Auth, Process & Filesystem Boundaries (`2a3daf86`, Wave 1B)

- **Zeroized secrets:**
  - New `af_models::secret_zeroize::{SecretString, SecretBytes}` wipe the full allocation on drop, print `[REDACTED]` from `Debug`, and compare in constant time.
  - They are adopted for the JWT signing key, `AES_MASTER_KEY`, OIDC PEM keys, peer and WireGuard secrets, plugin signing keys, and rotation-grace tokens.
  - `ProviderSettings` and `SettingsPayload` get redacting `Debug` impls.
- **Authentication & forwarding:**
  - `JWT_SECRET` must be at least 32 bytes after trimming and contain no ASCII control characters, or the API refuses to start.
  - Rotation-grace and session-successor maps are capped at 4096 entries, with a 60 s sweep.
  - `/refresh` sits behind the auth rate limiter.
  - A new outermost `normalize_peer_forwarding_middleware` strips `X-Forwarded-*`, `Forwarded`, and `X-Real-IP` from untrusted peers.
  - OIDC PEM files are capped at 64 KiB.
- **Process-group bounding ([`af-release/src/process_group.rs`](../../backend-rs/crates/af-release/src/process_group.rs), re-exported as `af_runner::bounded_command`):**
  - Every privileged child runs in its own process group, with output caps and group-wide kill on timeout or cancellation.
  - Legacy Bash installers are bounded to 3600 s wall clock, 64 MiB total output, and 64 KiB per line.
  - The runner drains for 20 s on shutdown.
  - The provenance verifier is capped at 1 MiB of output.
  - Dispatcharr admin credentials move from the process environment to stdin JSON.
- **Filesystem confinement ([`af-release/src/fs_security.rs`](../../backend-rs/crates/af-release/src/fs_security.rs)):**
  - Adds `O_NOFOLLOW`/dirfd primitives and a per-thread `fsuid` helper.
  - When root opens a service-owned SQLite database, lease, or `*arr` database, it does so under the owning user's `fsuid`.
  - Snapshots of databases in non-root-owned directories go through a `0700` root scratch copy, capped at 2 GiB.
  - Snapshots are written `root:root 0600`.
  - McBrowser walks are capped at 64 path components.
- **Release configuration (`af-release/src/config.rs`, `deploy/release-manager.sh`):**
  - `--config` files must be regular, non-symlink, root-owned, not group- or world-writable, and at most 64 KiB.
  - Only the 31 `ALLOWED_CONF_KEYS` are accepted. GitHub tokens and `AETHERFLOW_SKIP_PROVENANCE_VERIFY` are no longer honored from `--config`.
  - Release archives are limited to 512 MiB per entry, 2 GiB total, and 20,000 entries.
- **Rollback, locks & helpers:**
  - Deploy and rollback mirror-sync the release's `packages/` into `/opt/AetherFlow/packages/` and `/usr/local/bin/AetherFlow/`, pruning stale entries.
  - `af-certbot-sync` and `af-systemd-sandbox` become regular `0755 root:root` files.
  - The retired `/usr/bin/af-heal` is removed.
  - Release locks pin inodes (`verify_still_active`), and lease directories and files are tightened to `0750`/`0640`.
- **Transcode & plugin isolation:**
  - The transcode worker checks the `SO_PEERCRED` UID by default: the worker UID, `0`, and `aetherflow` are allowed, and `AF_TRANSCODE_ALLOWED_PEER_UIDS` overrides the list.
  - Plugin sandboxes add `/run/aetherflow-transcode*` to `InaccessiblePaths=`.
- **Installers:**
  - Inline Python uses `python3 -I`, and a safe SQLite reader replaces the `sqlite3` CLI.
  - SABnzbd and Calibre-Web build as their service users under `env -i`.
  - Palate stops sourcing `palate.env` (it reads only `PORT` and `PALATE_DB_PASSWORD`).
  - PostgreSQL `psql`/`pg_dump` calls run with scrubbed environments.
  - `librespeed.service` gets `ProtectHome=yes`.
- **Tests:** 103 new Rust tests across 31 files.

#### Operational, Plugin, Setup & Update-Watcher Hardening (`f7149aca`, Wave 2)

- **Plugin manifests ([`af-api/src/plugins/manifest.rs`](../../backend-rs/crates/af-api/src/plugins/manifest.rs)):**
  - In production, the plugins root, each plugin directory, and `plugin.manifest.json` must be owned by uid 0 and not group-writable by a non-root group.
  - Manifests must be regular, non-symlink files of at most 256 KiB, opened with `O_NOFOLLOW`.
  - Plugin iframe `postMessage` handlers verify `event.source` and `pluginId`.
- **Post-lifecycle DNS reconciliation:**
  - New `reconcile_post_lifecycle_dns_best_effort` rebuilds hosts and DNS-provider files from the database after every successful install, update, or remove, under a global mutex, via `OwnerScopedConnection`.
  - Certbot sync runs once, after commit.
- **Update watcher:**
  - Install, update, and remove bump a `package_lifecycle_epoch` and clear stale `app_updates` rows, so an old probe can never resurrect "update available" for a removed or just-updated app.
  - Failed version probes show "Installed version could not be confirmed" instead of raw stderr.
- **Setup:**
  - Setup takes an `flock` lock at `/run/aetherflow-setup.lock` before touching any state, and refuses symlinked lock paths.
  - Adds `ed` and `libapache2-mod-fcgid`, and enables `php<ver>-fpm`.
  - Writes vsftpd and `default-ssl` atomically.
  - Derives the default release tag from `.version`.
- **Tests:** 28 new Rust tests across 14 files.

#### Release Pipeline Integrity (`350852f9`, Wave 0)

- **Release identity:**
  - The `release-publish` job runs in the protected `release-publish` environment.
  - It publishes with `secrets.RELEASE_PUBLISH_TOKEN` and fails closed if the token is empty, is an ephemeral `ghs_*` token, or does not authenticate as `McEveritts`.
  - `GITHUB_TOKEN` drops to `contents: read`, keeping only the OIDC attestation permissions.
- **Concurrency ceiling:**
  - `max-parallel` caps and check→build DAG staging bound worst-case concurrency across CI, Security, Release, and Pages to 18 jobs or fewer.
  - Duplicate nightly push triggers are removed.
- **Artifact hygiene:**
  - A missing prebuilt ARMv7 `speedtest-backend` is now a hard error.
  - Archives use deterministic GNU tar flags (`--sort=name --format=gnu`, normalized modes).
  - `EGM.md`, `*_DRIFT_REPORT.md`, and `goldfish_review_report.md` are excluded from `git archive`, `build_gold.sh`, `build_wasm_frontend.sh`, and `create-plugin-sdk.sh`.

### 2. Distributed Jellyfin Transcoding (`d3934f0d`, `b1988922`)

- **Silicon probing:**
  - When `/usr/bin/vainfo` is present, workers probe each non-NVIDIA render node (`vainfo --display drm --device <node>`) and filter out encoders the GPU cannot run.
  - They report `hw_decoders` and `hw_encoders_verified` (UI badge: "Silicon verified").
  - `tonemap_vaapi` jobs route only to Intel nodes.
- **Vulkan Compute vs. Vulkan Video:**
  - Workers probe `ffmpeg -init_hw_device vulkan` for FFmpeg 8 and FFmpeg 7 log formats, and reject software renderers (`llvmpipe`, `lavapipe`, `swiftshader`).
  - Compute queues (`vulkan_compute`) are tracked separately from `VK_KHR_video_*` decode/encode codecs (`vulkan_video`).
  - The dispatcher skips workers without Vulkan Compute for libplacebo jobs.
  - Unverified `*_vulkan` encoders are hidden unless `AF_TRANSCODE_VULKAN_VIDEO=true`.
- **Load-aware dispatch:**
  - Workers are scored by weight, free slots, live CPU/GPU load, and tunnel RTT (`score_worker_candidate`).
  - Idle LAN workers with no load data keep exact operator weight ratios.
  - The tunnel `GET /health` reply now includes `load` (`cpu_usage_pct`, `gpu_usage_pct`).
- **Dispatch policies:**
  - New **Dispatch policy** (`remote_first` default, `local_first`, `balanced`) and **Local max jobs** (1–64) settings in Cluster → Jellyfin transcoding.
  - Stored in migration 28's `transcode_dispatch_settings` table and audited as `peer_transcode_policy_updated`.
  - Active local Jellyfin FFmpeg jobs are tracked via `SO_PEERCRED`.
- **Backend adaptation & tuning:**
  - `AF_TRANSCODE_ADAPT_BACKEND` (`off`/`gpu`/`prefer_qsv`/`all`) and an `AF_TRANSCODE_FFMPEG_THREADS` cap.
  - The worker unit adds a 512 MiB persistent Mesa shader cache (`CacheDirectory=aetherflow-transcode-worker`) and `/dev/kfd` access for AMD.
- **UI:**
  - Adaptation, Vulkan Compute (HDR), Vulkan Video, and silicon badges.
  - CPU/GPU/RTT telemetry, hardware-decode codecs, and the local active-jobs badge.
  - Translated in all 6 locales.

  - A help popover, a legend, and status-dot count chips.
  - A richer Service inspector with clickable incoming and outgoing peers and raw JSON.
- **Locales:** 34 new strings in each of the 6 locales.

### 4. Marketplace Ingress, TLS & Lifecycle (`b98e6e45`)

- **Managed `sites-enabled` symlinks:**
  - `snapshot_blueprint_targets()` accepts strictly confined `../sites-available/<same-name>` or absolute same-name aliases for managed vhosts, checked via dirfd `fstatat`/`readlinkat`.
  - It still fails closed on hostile targets and on symlinked directories.
  - Vhost backups restore before runtime and blueprint snapshots, so a live Apache reload fires correctly on rollback.
- **Vhost cleanup on remove:**
  - Package removal deletes `aetherflow-app-<app>.conf`, `aetherflow-ext-<app>.conf`, and `aetherflow-ext-<app>-le-ssl.conf` from `sites-available`/`sites-enabled`, in both the runner and API paths. Legacy `<app>.conf` files are left alone.

- **TLS-pending resync:**
  - New runner route `POST /v1/ingress/resync-tls` rewrites "TLS certificate provisioning pending" vhosts once a certificate covers their SAN. It is fault-isolated per vhost and reloads under `VHOST_LOCK`.
  - `/v1/certbot-sync` chains the resync.
  - `packages/system/af-certbot-sync` triggers it over the runner socket, with an `AF_CERTBOT_SYNC_FROM_RUNNER` recursion guard and an `SO_PEERCRED` owner check.

### 5. Sandbox & Peer Storage (`908e818d`)

- **Canonical drop-in:**
  - Only `/etc/systemd/system/<unit>.d/10-aetherflow-sandbox.conf` is written now.
  - The legacy unnumbered `aetherflow-sandbox.conf` is removed on install, reinstall, and update, so operator `20-*.conf`…`99-*.conf` overrides take precedence.
- **Group-shared media `UMask`:**
  - `UMask=0002` (was `0077`) applies to 32 shared-media, downloader, and `*arr` unit families: qBittorrent, Deluge, rTorrent, Transmission, SABnzbd, NZBGet, Sonarr, Radarr, Lidarr, Readarr, Bazarr, Jellyfin, Plex, Emby, Audiobookshelf, Kavita, Navidrome, and more.

  - Isolated apps keep `0077`.
- **Peer NFS GID warnings:**
  - Writable exports or mounts whose GID falls in the host-local dynamic system range (1–999) raise warnings.
  - The warnings appear in API logs and the audit trail, in `af cluster diagnose` (`gid_alignment_warning`), and in the Cluster Storage UI.

### 8. Release Integration Fixes (v4.0.2 release branch)

- **Merge resolution:** combines Wave 1B's `bounded_command` and `with_db_mut` sync with nightly's unconditional post-rollback Apache reload and remove-time vhost cleanup. It keeps both sides' sandbox `UMask`/`ProtectHome` controls and regression tests.
- **Clippy gate:** boxes the remote `DispatchChoice` variant (`large_enum_variant`). This failure had blocked every nightly CI, Security, and Release run since `d3934f0d`.
- **Gitleaks gate:** adds exact, path-scoped allowlists for the 33 synthetic Wave 1A/1B redaction and crypto fixtures that failed the working-tree and history scans.
- **Stale and non-hermetic tests:**
  - Aligns the current-schema test with migration 28 and scrutiny unit resolution with `scrutiny-influxdb`.
  - Pins fake transcode workers' DRM render nodes, so the weighted-selection and dispatch-policy tests no longer depend on the host GPU (`81b1bdb8`, `0df10f1d`). GitHub runners expose neither `/dev/dri` nor `/sys/class/drm`.
- **Flaky timing gate:**
  - New `backend-rs/.config/nextest.toml` runs the Wave 1A linear-time scaling regressions with the machine to themselves, with two bounded retries.
  - Assertions are unchanged, and recovered runs are reported as `FLAKY`.
- **Piped & Invidious database bootstrap (`1fd2eca7`):**
  - Wave 1B ran the PostgreSQL bootstrap through `os.execvpe("runuser", …)` with a scrubbed `PATH=/usr/local/bin:/usr/bin:/bin`. Debian and Ubuntu ship `runuser` only in `/usr/sbin`, so every Piped and Invidious install failed with `FileNotFoundError`.

That failed the embedded E2E runner before Playwright started, in every browser job. The checks now assert the tiered layout's computed viewBox, its empty-service canvas, and the Reset view control.
- **Installer test fixtures (`60d2aaba`):** 28 installer regressions are realigned with Wave 1B's `env -i` / `python3 -I` / `os.execve` isolation and the new `release-manager.sh` helpers. Mocks survive scrubbed child environments without escaping to host binaries. Production behavior is unchanged.

## Breaking Changes & Upgrade Guide

**There are no breaking API or CLI changes from `v4.0.1`.** Migration 28 is additive and applies automatically. Several hardening changes are stricter than before and may need operator action.

> [!IMPORTANT]
> **Check before upgrading:**
> 1. **`JWT_SECRET`:** it must be at least 32 bytes after trimming whitespace, with no tabs, CR/LF, or other control characters. Otherwise `aetherflow-api` refuses to start. Generate one with `openssl rand -hex 32`.
> 2. **`release-manager.conf` / `af release --config`:**
>    - The file must be a regular, root-owned, non-symlink file, not group- or world-writable, and at most 64 KiB.
>    - Only the 31 allowlisted keys are accepted.
>    - Move GitHub tokens and `AETHERFLOW_SKIP_PROVENANCE_VERIFY` into the environment or `/etc/aetherflow/aetherflow.env`.
> 3. **Plugins:** production plugin trees and manifests must be owned by `root` (uid 0) and must not be group-writable by a non-root group. Fix them with `chown -R root:root` and `chmod -R go-w`.
> 4. **Transcode workers:** the worker now accepts socket peers only from its own UID, root, and `aetherflow`. Set `AF_TRANSCODE_ALLOWED_PEER_UIDS` in `/etc/aetherflow/transcode.env` if anything else connects.
> 5. **Reverse proxies:** `X-Forwarded-*`, `Forwarded`, and `X-Real-IP` from untrusted peers are now stripped. Remote proxies must be listed in `TRUSTED_PROXIES` for client IPs to resolve correctly.

### Behavior changes to be aware of

- **Transcode defaults:**
  - The new `AF_TRANSCODE_OPTIMIZE_VULKAN_TONEMAP` defaults to `true`. It rewrites VA-API `tonemap_vaapi` HDR filter graphs to Vulkan Compute (libplacebo) on workers, and on controllers through the Jellyfin shim. Set it to `false` to keep the v4.0.1 behavior.
  - `AF_TRANSCODE_VULKAN_VIDEO` defaults to `false`, so `*_vulkan` encoders and `-hwaccel vulkan` jobs are no longer offloaded unless you enable it.
  - Under `remote_first`, choosing between workers is now load- and latency-aware.
- **Worker unit additions:** the Mesa shader cache and `/dev/kfd` take effect only when the worker unit is rewritten. To apply them, save **Cluster → Jellyfin transcoding** with the worker service enabled.
- **Sandbox drop-ins & `UMask`:** these apply the next time each app is reinstalled or updated, or when you run `sudo af sandbox apply <app>` and then restart the service. Afterwards, files those services create without an explicit mode are group-writable (`0664`/`0775`).
- **Package removal:** removing a package now deletes its managed `aetherflow-*` Apache vhosts.
- **Helper sync:** deploy and rollback prune unmanaged files under `/opt/AetherFlow/packages/` and `/usr/local/bin/AetherFlow/`, and remove `/usr/bin/af-heal`. Keep any customizations elsewhere.
- **Execution limits:**
  - Legacy Bash installers are killed after 1 hour or 64 MiB of output.
  - Root snapshots of databases in non-root-owned directories fail if the database, WAL, and journal together exceed 2 GiB.
- **Setup:** re-running setup requires `flock`, and the setup lock is now `/run/aetherflow-setup.lock`.
- **Redaction:** diagnostics and job summaries show more `[REDACTED]` markers than before. This is intentional.

### Upgrading from `v4.0.1` or `v4.0.x-nightly.*`

1. **Optional pre-upgrade snapshot:** create a WAL-safe backup via **Settings → Backups & Restore** or `sudo af backup create`.
2. **Review the checklist above**, especially `JWT_SECRET`, `release-manager.conf`, and plugin ownership.
3. **Deploy `v4.0.2`:**
   - From the Web UI: **Settings → System Updates** → choose the **Stable** (or **Nightly**) channel → **Update**.
   - From the CLI:
     ```bash
     # Stable channel (master / v4.0.2)
     sudo af release deploy --channel stable

     # Nightly channel (rolling v4.0.2-nightly.* prereleases)
     sudo af release deploy --channel nightly

     # Direct in-process fallback (without runner socket)
     sudo af release deploy --local --channel stable
     ```
4. **Rollback:** if `/health/ready` fails after the atomic symlink swap, `af-release` restores `.previous_release` automatically. To roll back manually: `sudo af release rollback --local`.

> [!NOTE]
> Upgrading directly from **`v3.2.x`**? Review the [v4.0.0 Release Notes](./v4.0.0.md#breaking-changes--upgrade-guide) and the [Upgrading Guide](../upgrading.md) first.
